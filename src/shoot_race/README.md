# shoot_race：射击小车比赛程序（第一阶段）

面向 2026 无人车任务挑战赛的新主程序：起点播报 → 识别区拍卡片识别靶号并播报 → 1/2/3 号任务点打环形靶、旋转靶、移动靶 → 终点播报。

这个包独立于旧程序：放在 `~/N8NNWC/src/shoot_race`，**不修改** 旧的 `robot_slam`、`N8NNWC.sh` 等任何文件，随时可以切回旧程序。

## 2. 模块与调用关系

```
race_node.py（入口）
  │ 读配置 → 创建模块 → 开局自检 → 设初始位姿 → 等输入 1
  ▼
MissionRunner（mission.py）  主循环 20 Hz：按 mission.yaml 依次执行步骤，管时间
  │ 每个周期：step.update(ctx) → ctx.publish_motion() → 检查完成/超时
  ▼
steps.py  每种步骤一个类
  ├─ SayStep        → voice.VoicePlayer
  ├─ DriveStep      → motion.PathFollower（或 move_base）+ motion.obstacle_in_path
  ├─ AlignStep      → geometry.fit_wall + motion.WallAligner
  │   （行驶、精定位都用 ctx.chassis = motion.ChassisModel 预测"松油门后停在哪"）
  ├─ RecognizeStep  → recognition.CardRecognizer（CardMatcher 离线 + VlmClient 豆包）
  ├─ ShootRingStep      → aiming.RingAimer（+ LateralShifter）→ shooter.Shooter
  ├─ ShootRotatingStep  → aiming.fit_wheel + RotatingPlanner（+ LateralShifter）→ shooter.Shooter
  └─ ShootMovingStep    → aiming.MovingPredictor → shooter.Shooter
        │
        ▼  所有传感器读取和速度输出都经过
ros_io.RosIO   全程序唯一接触 ROS 的类（测试时换成 tests/sim_world.SimIO）
```

|---|---|---|

| `geometry.py` | 角度、坐标变换、激光墙线拟合（RANSAC + 最小二乘） | 否 |

## 3. 比赛流程（mission.yaml 默认）

| 步骤 id | 内容 | 时间上限 |
|---|---|---|
| say_start | 播报比赛开始 | 5 s |
| go_recog | 去识别区（边走边转向，车头朝左墙卡片） | 8 s |
| recognize | 停稳 → 采集 0.4 s 图像选最清晰 → 识别 | 8 s |
| say_targets | 播报两个靶号 | 6 s |
| go_p1 / align_p1 / shoot_ring | 去 1 号点 → 贴墙精定位 → 打环形靶 | 8 / 6 / 8 s |
| go_p2 / align_p2 / shoot_rot | 退到通道 → 侧移 → 进 2 号框 → 精定位 → 打旋转靶 | 15 / 6 / 55 s |
| go_p3 / align_p3 / shoot_move | 同上，3 号点打移动靶 | 15 / 6 / 16 s |
| go_end / align_end / say_end | 去终点 → 精定位 → 播报结束 | 10 / 6 / 5 s |

**时间管理（对应规则）**
- 每一步都必须有 `timeout_s`，且 < 20 秒（规则：20 秒状态不变判结束），配置检查会拦住违规写法。
  唯一例外是旋转靶：转轮 43 秒一圈，最坏要等将近一圈；等待中每静止 12 秒左右平移 1.5 cm 再回来（keepalive），配置检查会确认 keepalive 开着。
- 打靶步骤有 `skip_if_less_than_s`（环形靶 35 s、旋转靶 40 s、移动靶 25 s）：比赛剩余时间不够就跳过，保住"到点""终点播报"这些确定的分。数值 = 该步 timeout + 后面必做步骤的典型用时，实车跑几局后按 `events.csv` 重新算。
- 任何一步超时都会进入下一步，不会卡死。打靶超时默认"照当前状态开火"（`on_timeout: fire`）。

## 4. 主要设计，以及和旧程序的对比

### 4.1 保留的旧程序优点
- **激光贴墙定最终位置**：旧程序 `move_to_position()` 用雷达到墙的距离精确停车，这是好思路，新程序保留并改进（4.4）。
- 串口发射协议、开火"开始→停止"间隔、环形靶两发之间 1.2 s 的硬件恢复时间。
- find_object 的环形靶模板（28~31）和 `/object_position` 接口；ar_track_alvar 的 AR 码识别。
- 任务点之间先退到下方通道再平移的路线。
- 输入 1 启动（`keyboard_start.py` 的做法：select 轮询终端，Ctrl+C 能及时退出）。

### 4.2 结构：一个主循环说了算
旧程序在识别回调里直接导航、开枪，多个线程同时往 `/cmd_vel` 发指令，阶段靠全局变量切换。
新程序：回调只存数据（RosIO），所有决策在主循环里按步骤执行；速度只有 `RosIO.send_velocity()` 一个出口；每一步有明确的开始、更新、超时、结束。

### 4.3 行驶：按底盘实测响应设计的路径跟随（drive_mode: direct）
**2026-10-17 全流程录包（full_212336.bag，/cmd_vel 对比 /wheel_odom 和 AMCL 位姿）实测的底盘特性**，决定了现在的做法：
- 发出速度指令后约 0.35~0.5 秒才开始动，再按时间常数约 0.3 秒跟上；停车同样要滑 0.6 秒左右。
- 稳态只能跑到指令的一部分：后退约 0.9、横移约 0.8、前进 0.6~1.0（横移完再前进最低，原因待查）。
- 边走边转打满 1.5 rad/s 时轮子饱和：实际只转到 1.3，平移只剩一半，车看起来一边打转一边乱滑。
- 低速小指令（< 0.05 m/s、短于 0.3 秒）底盘常常根本不起步。
- 位姿（AMCL + 里程计）位置 1 cm 一跳、朝向 0.5 度一跳；AMCL 朝向本身会差 4 度左右。

旧版跟随器（直线走路径点、比例控制朝向）没考虑这些：拐角处指令已经换方向，车还沿原方向滑 1 秒（冲过 8 cm）；
仿真加入实测延迟后，旧版到终点冲过 9~17 cm，去识别区、去 1 号点停不下来。

**做法（`motion.ChassisModel` + `motion.PathFollower`）**
- `ChassisModel`：记录每个周期真正发出的指令（`Context.publish_motion`），按"死区 + 一阶惯性 + 各方向增益"估计车速，
  并预测"现在开始发零速度，车会滑到哪里停下"（`predict_stop`）。参数在 system.yaml `chassis`，来自录包拟合。
- 跟随器每个周期先算预测停车点，后面全用它：
  - 方向：预测点投影到"起点 → 各路径点"的折线上，沿折线往前 `lookahead_m + lookahead_s × 车速` 取引导点，速度指向引导点 → 拐角变成圆弧，偏离路线会被拉回；
  - 速度：min(`max_speed`, √(2·`decel`·剩余路程), 拐角前按 `corner_speed` 降速)；预测点到终点就收油门，靠滑行到位；
  - 朝向：每段终点规定的朝向，按预测朝向比例控制，限 `max_yaw_rate`（1.0 rad/s），1 度以内不修；
  - 换算到车体坐标系用"指令真正起作用时"的朝向（边走边转时差十几度）；
  - `|vx|+|vy|+wheel_k·|wz|` 超过 `wheel_limit` 时按比例缩小平移（方向不变）；输出加约 0.1 秒低通，位姿的小跳动不变成方向抖动。
- 结束：离终点 < `goal_tolerance` 且朝向在 `yaw_tolerance` 内；或车已停住、离终点 < `close_finish_m`（8 cm）——不再低速点动，交给精定位。
- 车停着时不做预测（低速底盘不起步，模型会以为在动，22:06 实测导致反复"点一下停一下"）。
- 仿真对比（`tests/sim_world.py` 按实测延迟，参数故意和程序里的模型不完全一样）：新版停在终点 0.2~2.8 cm 内，旧版冲过 9~17 cm。
  限速 0.2 时行驶用时和旧版差不多（去 2 号点约 16 秒）；省时间靠提速到 0.3~0.35 和精定位变短。
- 通道（v26）：通道点的前后位置按激光量后围栏定（field.yaml `lane_wall`），和 AMCL 偏多少无关；爆发段贴着路线走，偏了先纠偏。
- 行驶时用激光检查运动方向前方有没有障碍，停车距离 `stop_distance + v²/(2·brake_decel) + v·sensor_latency_s`，发现障碍立即发零速度。
  v26 起按"车身矩形沿运动方向平移，会不会碰到 / 擦过（间隙 < side_margin）"精确算。
  离终点不到 `finish_if_blocked_within`（0.25 m）被墙挡住时：朝向没转完就原地转完，然后交给精定位。
- 保留 `mode: move_base` 作为备用（system.yaml 全局设置，或 mission.yaml 某一步单独设置）。

### 4.4 贴墙精定位（align）
- 对每面墙：取该侧 ±30° 内、距离在"预期墙距 ±0.4 m"内的激光点，RANSAC 找出共线点，再最小二乘拟合直线，得到**垂直距离**和**墙的偏角**。
- 前后、左右、朝向同时比例控制。车跑得快（> 0.06 m/s）时按预测停车点的误差算速度，不冲过头（2026-10-17 不预测时冲过 4~5 cm 再倒回）。
- 容差 0.8 cm / 0.5°，连续 3 个周期满足才算完成。
- **墙线核对**：定朝向那面墙的偏角和"AMCL 朝向推算的偏角"差超过 `misfit_deg`（12°）→ 这面墙只用距离、不按它转向。
  2026-10-17 终点框在墙角，后方扇区同时扫到两面墙，拟合出一条斜 16° 的线，精定位照着它把车扭了 17°。阈值不能太小：AMCL 朝向自身差约 4°。
- 需要的墙连续 `missing_finish_s`（1.5 秒）看不到、看得到的都已到位 → 提前结束，不干等到超时。
- 精定位完成时记下地图位姿（events.csv 的 `pose` 事件，`ok=1` 表示正常完成）；菜单 12（`teach.py adopt`）把它写成同名路径点，下一局行驶直接停到这里附近。
- 偏角符号：机器人逆时针偏 ψ，墙在机器人坐标系里的方向向量为 (sinψ, cosψ)（前/后墙）或 (cosψ, −sinψ)（左/右墙），所以 ψ = atan2(ux, uy) 或 atan2(−uy, ux)，四面墙都是逆时针为正。单元测试验证过。

### 4.5 环形靶（静止）：停稳看 → 横向平移过去 → 停稳再看（前后几轮合并估计）
**2026-10-16 晚 13 个环形靶录包（菜单 4/5 自动录的 shoot_ring_*.bag）分析结果**，决定了现在的做法：
- find_object 只有约 **2.6 帧/秒**（0.38 秒一帧），不是之前假设的 10 Hz；车完全静止时单帧靶心像素噪声标准差约 **3 像素**（5%~95% 分位 ±4.9）。
  旧做法"3 帧中位数、容差 2.5 像素"等于抽签：11 次运行里 2 次来回修正（-2.8 → +2.8 → -6.0 像素）直到 8 秒超时。
- 车横向平移时，find_object 的像素只变化理论值 fx·Δy/D 的约 **0.55 倍**（8~10 次平移回归；平移量用激光侧墙测，和卷尺量的一致）。
  旁证：三次试射反推弹着点，按理论 3.5 像素/cm 换算得 370 / 358.5 / 364.8（相差 11 像素），按 0.55 倍（1.94 像素/cm）换算得 365.8 / 363.4 / 366.4（相差 3 像素）。
  原因可能是模板里带了远处背景。所以平移量 = 偏差 / (fx × `image_gain`) × 距离，否则每次只修正一半多。
- 每次平移车身朝向会偏 0.1~0.4 度（激光侧墙偏角），画面跟着偏 1~4 像素；平移前看到的结果换算到新位置后不完全可信。

**做法（`aiming.RingAimer`）**
- **look**：车停稳 `settle_s` 后再等 `vision_latency_s`，之后收到的帧才用；同一位置的帧叫"一轮"，取中位数。
  当前估计 = 本轮中位数和之前各轮"换算到当前位置"的结果按可信度加权（方差 = 识别噪声/帧数 + 换算误差 `model_error` × 换算量 + 每次平移的朝向误差 `shift_yaw_px`）。
  平移量小时旧帧能帮上忙（平移后只需再看 `recheck_frames` = 2 帧），平移量大或换算不准时自动以新帧为主；新一轮和旧估计差超过 `reset_px` 就丢掉旧的。
  - 偏差 ≤ `tolerance_px`（3 像素 ≈ 1.5 cm）→ 开火；
  - 偏差在 `tolerance_px` ~ `look_more_px`（6 像素）之间、本轮不到 `max_look_frames` 帧 → 原地多看（一帧 0.4 秒，比平移 + 停稳约 2.5 秒便宜，也不会被噪声带着来回平移）；
  - 否则 → 平移。
- **shift**：用激光测的侧墙距离闭环平移（`aiming.LateralShifter`，参数在 system.yaml `lateral_shift`），到位或卡住（`stall_s` 内没进展）回到 look。累计平移不超过 `max_shift_m`（2026-10-25 起 2.5 cm）；已经顶到上限还偏 → 直接开火，不干等到超时。
- **2026-10-25 车出框**：6 局整局里 1 号框精定位到位（墙距差 ≤ 0.8 cm）后，靶心都在弹着点右边（按精定位朝向误差折算到"朝向正好"约 16~18 像素 ≈ 7 cm），
  每局都顶满 5 cm 平移，最后一局打中 10 环但车出框。弹着点本身没错：开火时靶心在弹着点右 2.7 像素，弹孔在靶心左约 1 cm，按 `aim_x_px` 公式算出 350.8（现在 350.5）。
  改法：靶偏的大头用车头朝向吃掉——`teach.py turn p1 -1.6`（1 号框精定位朝向 -1.18 → -2.78 度、路径点 p1 朝向 4.1 → 2.5 度，车角只多出约 0.5 cm），
  剩下的几个像素平移修，`max_shift_m` 5 → 2.5 cm（框左右余量约 4.5 cm）。精定位朝向容差 0.5 度 ≈ 5 像素 ≈ 2 cm，仍在平移上限内。
  回退：`config/field_taught.yaml.bak_1025r`、`config/shooting.yaml.bak_1025r`。
- **蒙特卡洛对比**（`tests/ring_monte_carlo.py`：用录包里的噪声、帧率、平移起步延迟，初始偏差 ±10 像素，各 300 次）：

  | 情况 | 旧做法：用时中位 / 超时 / 偏差 90% | 新做法 |
  |---|---|---|
  | 倍数 0.55、平移带朝向偏差 | 4.4 s / 36% / 2.7 cm | 4.1 s / 3% / 2.2 cm |
  | 倍数 0.55、无朝向偏差 | 4.4 s / 18% / 1.6 cm | 4.0 s / 1% / 1.6 cm |
  | 倍数实际是 0.8（`image_gain` 设错） | 4.3 s / 26% / 1.8 cm | 4.2 s / 6% / 1.6 cm |

  新做法主要是不再超时、不来回平移；弹着偏差受识别噪声限制（单帧约 1.5 cm），和枪本身的散布（±2~3 cm）相当。
- **为什么用激光、不用里程计**（菜单 19 底盘诊断的横移测试）：低速平移起步慢（0.05 m/s 要 0.4 s 才动、0.02 m/s 不动），麦轮侧滑让里程计把横向位移高估约 3 倍；底盘驱动的里程计位置本身也只有 1 cm 分辨率（驱动源码：位置按整数 cm 上报，速度按整数 cm/s、0.01 rad/s 下发，小数直接截掉）。
- **为什么平移、不转向**（菜单 19 底盘诊断的原地转测试）：这台麦轮底盘原地转向死区很大，0.3 rad/s 以下完全不转，0.5 / 0.7 / 1.0 rad/s 转 1 秒只转出指令的约 23% / 26% / 32%，做不了零点几度的精细转向。
- 为什么不边移边看：find_object 2.6 帧/秒、延迟 0.1~0.4 秒，边动边看看到的是"过去"的位置，会来回摆、过冲。
- 接受 28~31 全部模板编号（同一个靶；实测全部匹配成 31）。
- **换场地后复核**：菜单 4（演练）至少做两三次、让车平移过，然后菜单 18 分析录包，按输出改 `image_gain`、`frame_noise_px`。

### 4.6 旋转靶、移动靶
旧程序"追着打"：车一直转着追码，开枪前不刹车，没有提前量。车上诊断记录显示旋转靶 100 帧里两个条件同时满足 0 次。
新程序两个靶都基于 2026-10-16 在 2025 场地录的包（rotating.bag、moving2.bag）设计，坐标全部用像素：
AR 位置 (x, y, z) → u = fx·x/z + cx，v = fy·y/z + cy。不用 ar_track_alvar 给的"米"：车上 `marker_size` 参数（9）和码的实际尺寸不一致，
米制坐标整体放大约 2.9 倍（深度读 4.3 m，实际约 1.5 m），但 x/z、y/z 不受影响。

**旋转靶（`RotatingPlanner`；2026-10-23 起默认 `RotatingServo` 边看边对，见第 8 节 v30）**
- 实测：转轮 43 秒一圈（8.4 度/秒，画面里顺时针），5 个码在同一个圆上（半径约 29 像素 ≈ 6.4 cm），码之间约 72 度，大部分帧 4~5 个码同时可见。
- 车不能精细转向，也不能调枪口高度。候选点：圆周上离弹着点最近的点（车不动，偏差 = |弹着点到圆心距离 − 半径|），以及圆和"弹着点高度水平线"的两个交点（要横向平移）。
- **优先不平移**（2026-10-17 晚 5 次实测）：横移开环误差大，指令 15 mm 实际走 26 mm（死区约 0.3 秒里继续滑），车身还偏 0.2~0.4°（3~5 像素），修正用完只能偏 4~9 像素开火；
  而精定位靠墙闭环，那 5 次若不平移、在最近点开火，偏差是 0.1 / 2.6 / 3.0 / 3.9 / 3.9 像素。所以最近点偏差 ≤ `hit_tolerance_px` 就直接等它；超出才平移到交点。
  平移（`LateralShifter`，环形靶共用）按激光实测横向速度 × `coast_s` 提前收油门。
- 流程：停稳观察 1 秒 → 拟合圆心、半径、转速（`fit_wheel`）→ 选候选点 → 必要时平移、再观察 → 等待：每个周期重新拟合，目标码到点时间 = `latency_s` 时开火。
- 等待中静止满 `keepalive_still_s`（12 秒）且离开火还早，就后退再前进各 `keepalive_nudge_s` 秒，防止"20 秒状态不变"被判结束。前后挪只改距离，画面里转轮几乎不动。
- 等待超过 `max_wait_s`（50 秒）或会挤占后面任务的时间（`reserve_after_s`）→ 放弃；但放弃前至少观察 `give_up_observe_s`（3 秒）确认转速：
  1 秒的数据转速误差可达 30%（2026-10-16 同一转轮三次估出 8.3 / 10.7 / 8.0 度/秒）。连续 5 秒看不清转轮 → 不干等，按 on_timeout 开一枪走人。
- 2026-10-16 车上演练（不发射）：观察 1.4 秒 → 平移 33 mm → 再观察、修正 6 mm → 等 8.4 秒 → 在预测时刻"开火"，开火时预测误差 2.3 像素（约 0.5 cm）。
  当时第一次运行转轮电量低（3.8 度/秒，要等 67 秒）→ 正确放弃。实弹运行到 25 秒时车没电，没有结果。
  rot3.bag（8.3 度/秒）回放：4 次在录包时间内等到的交点，开火误差 0.3~0.5 像素（≤ 0.1 cm）。
- 码被认成旁边的码（实测会发生）：转速用"相隔 0.5 秒两点的角度差"取中位数，每个码再剔除相位偏离超过 8 度的点，不受个别坏点影响。

**移动靶（`MovingPredictor`）**
- 实测：滑块匀速往返约 18 像素/秒（≈ 4 cm/s），单程约 6.8 秒、行程约 121 像素；到端点立即换向，换向约 0.5 秒。三个码间距约 27 像素。
- 车不动。先去掉误识别（和前后邻居的中位数差 > 8 像素的帧；不和自己比、两端不补值，最新一帧是坏点也能剔除），最近 0.3 秒拟合直线得位置和速度。
- 不开火的情况：速度 < 8 像素/秒（正在换向）；最近 0.6 秒前后两半方向不一致（刚换向）；前方行程端点已知、弹丸到达时离端点 < 6 像素（快换向了）；速度 > 40 像素/秒（数据有问题）。
- 开火时机：剩余时间 = (枪口 − 当前位置) / 速度，等于 `latency_s` 时开火（不是"一进容差就开"，那样总在容差边缘开火）。目标静止（手扶着测试）且在容差内直接开火。
- 用图像时间戳外推到"现在"，识别处理延迟自动扣掉；`latency_s` 只包含"决定开火 → 弹丸到靶"。所以 **AR 帧率必须 ≥ 13 Hz**（0.3 秒内至少 4 帧），`bringup.launch` 已把 ar_track_alvar 的 `max_frequency` 改成 30。

**用真实录包回放验证**（录包时车静止，弹着点放在不同位置）：
- 旋转靶：7 次能在录包时间内等到的交点全部开火，弹丸到达时目标离弹着点 0.1~0.7 像素（≤ 0.15 cm）。
- 移动靶：3 个码 × 9 个弹着点（含靠近两端的）全部能开火，共 87 次，误差中位 0.36 像素、95% 在 2.5 像素以内、最大 3.7 像素（码宽约 14 像素）。
- 这只验证"时机算得对"；弹着点 `aim_u_px/aim_v_px` 和 `latency_s` 仍要实弹标定。

### 4.7 识别区：两种方法互为备份
- **离线两步模板匹配**：ORB 特征点 + 单应性把照片拉正到模板坐标，再只比较题目文字区的相关系数。（同一水果的 5 张卡水果图完全一样，只数特征点会认错，所以要第二步。）合成照片测试 30/30 正确，约 0.3 秒，不需要网络。
- **豆包视觉模型**：标准库直接调用火山方舟 OpenAI 兼容接口（Python2 也能用），提示词要求输出 `{"answer": 3, "fruit": "杨桃"}`。
- **策略**（recognition.yaml 的 policy）：默认 `vlm_first`（等豆包最多 6 s，失败用离线）；离线方法在真卡片上验证可靠后建议改 `offline_first`，可省 2~5 秒；现场没网用 `offline_only`。全部失败时用离线的最佳猜测或默认靶号，流程不会停。

预录音频离线播放（不依赖网络和讯飞账号）。播报前先停车并确认轮速计速度为 0（规则要求播报时静止）。
